# 整机与碎卡混合调度、通信和成员切换计划

2026-11-07开始；本页是执行计划，完成状态以实验记录为准。

目标：把Ready节点级CPU/内存/NPU资源纳入调度，优先16/8/4/2卡共享设备域作业、剩余单卡；无空闲时只提交有预算的LOW单卡排队。验证多卡容器内HCCL能否使用机内通路，比较相同卡组上的flat与显式层次SUM，最后在COMMIT边界接入候选状态对齐和切换。

并行分工：节点API/资源规划、HCCL路径/层次通信、候选切换安全状态机；主会话整合多卡worker入口、调度与运行时、实验资源和独立审计。所有实现位于本独立项目，不把最初实验工程作为隐式依赖；私有站点配置和实验产物另存共享工作目录。

后续按用户最新并发约束调整为最多一个 subagent：由其检查并修复调度锁和候选申请边界，主会话负责资源清理、真实实验、数值审计、文档和最终集成。平台实验顺序运行，避免 64 卡实验与候选池相互挤占预算。

1. 只读核实官方节点视图接口与节点选择语义，去重两个空间的物理节点，保留观测时间、Ready、CPU/内存/NPU余量和规格。未知、过期与不可调度数据不能当空闲资源。
2. 形成可审查的16→8→4→2→1计划；多卡请求必须使用已发现的规格，实际调度后核对官方节点/设备身份。计划节点不能冒充已获配节点。
3. 扩展每作业多worker启动，保留分配的设备mask，在完整可见设备集合中按local rank选择逻辑设备。先跑小模型global256/atomic4/no-recompute，核对完整样本覆盖、loss、梯度范数和最终Adam。
4. 对相同设备做flat/层次/flat对照；用有代表性的通信字节、正确同步和数值检查，记录机内/机间路径、预热、正式轮次与最大rank耗时。timeout与算法分别变化，不能凭最终synchronize等待推断丢包。
5. 候选模型load与当前状态对齐分开：只有最新完整模型/Adam/step一致后才允许COMMIT边界切换；试运行成功前保留旧成员。释放与热备互斥；旧版本状态不可直接顶上。未接入真实controller的纯状态机不能当作已实现自动热切换。
6. 以实际功能/故障/通信证据更新指导文档，保留当前已验证基线；新运行时代码更新manifest，不覆盖历史验收记录。

资源：沿用最多64张的总实验预算，活动+加载候选+保留热备+未知提交/排队预留全部计入。新功能先用较小活动组，给候选留空间；不停止其他项目的作业或保活监控。当前其他任务的暂停文件不由本任务清理；本任务自己的暂停文件必须finally移除。

主要待证假设：QZ是否可按节点申请多卡；16卡的真实HCCS/跨域通路；显式分层是否优于HCCL自带分层；候选加载及完整状态同步的暂停是否能由持续收益摊销；整pod抢占会同时丢失多个rank，需要独立故障验收。
